# 架构与逻辑正确性审查规则

本规则用于审查变更全貌合理性、架构分层合规性、扩展性设计、接口设计、数据库设计、缓存与中间件、依赖与版本、业务逻辑正确性、异常处理、事务一致性、需求逻辑验证、OpenSpec 工作流合规等架构与逻辑层面问题。架构与逻辑问题优先级最高，必须在其他审查之前完成。

优先级定义和通用审查执行指引见 `common-review-guide.md`。

## 本轮特有指引

1. **架构优先**：先查架构再查代码，架构问题不解决，代码级审查无意义。

### 9.2 OpenSpec 工作流合规

> **前置条件（强制）**：仅在指定了 `--spec-dir`（即 `bundle.json` 包含 `specDir` 字段）时执行本节审查。未指定 `--spec-dir` 时，**禁止读取任何 OpenSpec 相关文件，禁止执行本节全部规则，禁止产生 `category` 为 `OpenSpec合规` 的发现项**。不得以任何理由绕过此前置条件。
