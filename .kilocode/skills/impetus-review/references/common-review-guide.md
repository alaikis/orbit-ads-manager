# 审查公共指引

本文件为六轮审查规则文件的公共引用，包含优先级定义和通用审查执行指引。各规则文件通过引用本文件避免重复。

## 优先级定义

每条规则标注优先级，审查时**必须按优先级顺序执行**：

| 优先级 | 含义 | 审查要求 | severity 映射 |
|--------|------|----------|---------------|
| **P0** | 阻断级 — 架构错误、安全漏洞、逻辑错误、线上必崩 | **必须逐条检查**，不可跳过，违反即阻断 | `high` |
| **P1** | 严重级 — 性能隐患、边界未处理、规范严重违规 | 应逐条检查，除非上下文明确无关 | `medium` |
| **P2** | 优化级 — 命名、注释、代码冗余、可维护性一般 | 按需检查，优先级低于 P0/P1 | `low` |

**severity 映射规则**：规则优先级与 findings 严重级别**固定绑定**，禁止按主观判断调整：
- P0 → `high`
- P1 → `medium`
- P2 及其他 → `low`

## 通用审查执行指引

1. **优先级驱动**：先查 P0 → 再查 P1 → 最后查 P2，P0 发现问题必须报告，不可因时间跳过。
2. **变更聚焦**：仅审查本次变更涉及的文件和逻辑，未变更代码不纳入审查范围。
3. **规则去重**：同一缺陷命中多条规则时，在最高优先级规则下报告一次即可。
4. **误报抑制**：规则示例为典型场景，审查时需结合上下文判定，避免机械匹配导致误报。
